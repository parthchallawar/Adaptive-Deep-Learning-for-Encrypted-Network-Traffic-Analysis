# Decision log

Decisions that shape the project, each with its reason, so nobody has to re-argue them. Newest last. Add an entry whenever a decision closes a real alternative. A decision is changed by adding a new entry that names the one it replaces, never by editing history.

| # | Date | Decision | Why | Consequence |
|---|---|---|---|---|
| ADR-001 | 2026-09-17 | Metadata only: packet size, direction, inter-packet time, push flag. No payload bytes | Works under TLS 1.3, ECH and QUIC; privacy; fits Kaggle | Byte-level foundation models are baselines we cite, not build |
| ADR-002 | 2026-09-17 | `K_MAX = 30` payload packets, CESNET DataZoo column order | Matches the published corpora, so PCAP-derived and published flows are interchangeable | Changing any constant in `data/ppi.py` means re-exporting every shard |
| ADR-003 | 2026-09-17 | Primary dataset CESNET-TLS-Year22, temporal splits by ISO week | The only year-long public corpus; real drift | Splits: train 11–26, val 27–30, test 31–34, drift 35–52 |
| ADR-004 | 2026-09-17 | No containers. SQLite. Everything runs as a local process | One developer, one Windows laptop | Spec 019 deferred; no Docker artefacts in the repository |
| ADR-005 | 2026-09 | Tracking in two layers: a dependency-free run directory, then a sync into a local SQLite MLflow store | Kaggle has no MLflow; MLflow 3.x rejects the file store | `tracking.py` must import without mlflow; never use `file:` URIs |
| ADR-006 | 2026-09 | Resume is bit-exact; a run resumed under a different config, label space or standardizer raises | Kaggle sessions end; silent drift between sessions would be undetectable | Data order and dropout derive from `(seed, epoch)` |
| ADR-007 | 2026-09 | Saved logits carry their indexing (`effective` for causal models, `nominal` for per-K models) | Filing per-K outputs at the effective slot makes different models' answers collide | Every K-based metric takes a `DenseLogits` |
| ADR-008 | 2026-10-03 | B1 (XGBoost) removed | Its real D1 run never completed | Code is in git history at `0550054`; `prefix_stats.py` has no consumer |
| ADR-009 | 2026-10 | Open-set split `d1_open`: 150 known classes, 30 held out, drawn once at design time | Real unknown flows in val and test | The same 30 classes are unknown in val and test (see ADR-016) |
| ADR-010 | 2026-11-15 | Recommended PAT recipe: dropout 0, label smoothing 0, 8 epochs (`ft_pat_{,ssl_}d1_tuned.yaml`) | Each default cost about one point of AUC_K in single-change ablations | `ft_pat_d1.yaml` is frozen as the ablation reference |
| ADR-011 | 2026-11-17 | H1 is reported as partly supported and H5 as not supported | Three seeds: SSL gains 6–7 points at K ≤ 3, misses the K = 5 bar; SSL adds no robustness | The robustness claim is about prefix training, not SSL |
| ADR-012 | 2026-11-17 | Phase 4 replays everything from compact per-flow score files; `proj` is never saved | Full logits are ~2 GB per run and slow to pull; `proj` would be as large again | One model pass per (run, split); policies and controllers are NumPy |
| ADR-013 | 2026-11-17 | `src/adl_etc/inference/` is torch-free and is the single implementation of the decision rule, unknown scorer, controller and drift monitor | Offline evaluation (no torch allowed) and the online service must share one implementation | A test enforces the import rule and offline/online equality |
| ADR-014 | 2026-11-17 | The 2026 NBFC payment-API fraud story is used as motivation only. No fraud-detection claim. No traffic recording before phase 6 | The project was never trained or tested on such traffic; a simple handshake fingerprint (JA4) already separates careless tools; a careful attacker using the genuine client's software would look the same in 30 packets; proper keys (mTLS, request signing) are the real fix | `docs/future-work.md` FEP-1 holds the idea and an optional one-day demo |
| ADR-015 | 2026-11-17 | CESNET-CC25 rejected as a dataset; TQH-C2 kept only as an optional demo | CC25: attack flows are unencrypted, 9 in 10 have one or two payload packets, patterns repeat heavily, and attack and benign traffic were captured at different points. TQH-C2: its authors' simple baseline already scores about 1.00 | No attack dataset enters the main results |
| ADR-016 | 2026-11-17 | Policy and unknown-score defaults are fixed before any test number is seen (`β = 0.5`, `k_min = 2`, `k_ood = 3`, `f = 0.02`, rejection first); alternatives are reported as sensitivity, never used for selection | Val and test share the same unknown classes, so tuning on unknown val flows would leak | A test asserts unknown val flows cannot change a fitted artefact |
| ADR-017 | 2026-11-17 | P-RL is offline fitted-value stopping on `(confidence, margin)`, not a re-implementation of FastFlow | The baseline was deferred twice; a CPU-only, deterministic version is enough to answer "does a learned stopper beat ours on the same backbone" | The paper names it as our version |
| ADR-018 | 2026-11-17 | Spec 011's "compute" budget metric is descoped; the controller targets mean K and p95 K | Depth exits were never built | Recorded as correction C6 |
| ADR-019 | 2026-11-17 | The main demo replays stored flows from `test_id` / `test_drift`; PCAP upload is a second scene | D1 has no PCAPs, so only shard replay shows in-distribution traffic, real unknown classes and real drift | Spec 016 gains `POST /ingest/shards` |
| ADR-020 | 2026-11-17 | Service version 1 recomputes the prefix per packet; database access is synchronous with one writer thread; the dashboard polls | Identical outputs with far fewer failure modes on one Windows laptop | Corrections S3, S4, S6 in the phase-6 plan |
| ADR-021 | 2026-11-17 | Plans for phases 5–7 were drafted ahead of time | The owner asked for a full blueprint while the strongest model was available | They are drafts; each is re-checked at its phase start, as `specs/README.md` requires |
| ADR-022 | 2026-11-18 | Phase 4 closes with H2's and H3's failed bars reported as verdicts; the improvements (reject from packet 2, a non-uniform false-alarm spread over K, per-K score choice, a P-RL-style stopper on the safe-stop signal) are not built | The owner is short of time and the phase's exit rule asks for verdicts, not passes; anything built now would be chosen after seeing test numbers and would need held-out known classes as fake unknowns to stay honest | Listed in `docs/future-work.md` FEP-9; the thesis claims only what `docs/results-phase-4.md` supports |
| ADR-023 | 2026-11-18 | Controller gains are chosen on validation over `kp` up to 6, and settling time is reported two ways (strict and noise-robust) | The first search stopped at `kp = 2.0` (its grid edge) in every run; the strict settling count measures window noise (5% at 2,000 flows) as much as the controller | The second metric was added after the first failed, which the results document says; spec correction C10 |
| ADR-024 | 2026-11-18 | Phase 5 builds drift monitoring and the efficiency benchmark only; label-free adaptation, the canary alert, ONNX Runtime and int8 are not built | The owner is short of time; the roadmap already set adaptation as optional (DP-5a) and ONNX as time-boxed | Listed in `docs/future-work.md` FEP-3 and FEP-10 |
| ADR-025 | 2026-11-18 | Weekly drift metrics use equal-sized weekly samples; the early-vs-late decay interaction and the monitors' false-alarm rate are reported as not supported or not measurable, not claimed | Macro-F1 is biased low on small samples; there is no stationary stretch of data | `docs/results-phase-5.md` |
